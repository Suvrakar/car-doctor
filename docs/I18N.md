## How it works
- **English and Bangla** are written side by side at each call site: `t("Engine oil", "ইঞ্জিন অয়েল")` in the UI, `L10n(en, bn)` in templates and symptom trees.
- **Every other language** comes from a catalog, `core/src/main/resources/i18n/<code>.json`, mapping the English text to the translation. `Lang.pick(en, bn)` and `L10n.get(lang)` look it up.
- **Placeholders**: catalog keys use `{0}`, `{1}` for values that change ("{0} km left"). At runtime the formatted English ("1,250 km left") is matched against these patterns, most specific first, and the values are carried into the translation.
- **Fallback**: a phrase missing from a catalog shows in English, so a partial catalog never breaks the app.
- **Layout direction** follows the Android per-app locale (`AppCompatDelegate.setApplicationLocales`), so Urdu and Arabic mirror automatically; directional icons use `AutoMirrored`.
- **Speech input** uses the language's speech tag (e.g. `hi-IN`, `ar-SA`). The offline voice parser understands English and Bangla; other languages go to the on-device or cloud AI step.

## Adding or fixing a translation
```bash
python3 tools/extract_strings.py > tools/i18n_keys.json   # after adding new UI text
# edit tools/i18n_src/<code>.1.txt / .2.txt  — one "index|translation" line per phrase
python3 tools/build_i18n.py                              # validates and writes the catalogs
```
`build_i18n.py` rejects lines whose `{n}` placeholders differ from the English and reports missing phrases. `CatalogTests` checks every catalog is complete.

## Adding a language
1. Add it to `Lang` in `core/.../model/Localized.kt` (code, native name, RTL flag, speech tag).
2. Add the code to `app/src/main/res/xml/locales_config.xml`.
3. Write `tools/i18n_src/<code>.*.txt` and run `build_i18n.py`.

Translations were written for this release and should be reviewed by native speakers before launch in each market, especially safety advice in the symptom trees.
